# BINANCE_USDM_FUNDING_SOURCE_FORENSICS_V0

## Scope and verdict

This is a bounded source-contract investigation for the frozen Breadth V2
execution contract. It does not acquire the campaign dataset, run a strategy,
or implement the funding materializer.

**Verdict: `BLOCKED`.** The official sources expose exact funding time and rate,
and the REST response defines an associated mark price, but the required
historical Breadth V2 domain is not safely reproducible: sampled 2022 panel
events have `markPrice: ""` in REST, while the official archive has no mark
price column. No OHLC, index, premium, or nearest-time price substitute is
permitted by the frozen contract.

## SOURCE FORENSICS

### REST `/fapi/v1/fundingRate`

**SOURCE-SUPPORTED FACT.** Current official documentation defines:

```text
symbol       string
fundingRate  string
fundingTime  int64 milliseconds
markPrice    string (mark price associated with the particular funding fee charge)
rateType     Regular | Special
```

The documentation states that `startTime` and `endTime` are inclusive, the
default limit is 100, the maximum is 1000, and the endpoint shares a
500/5-minute/IP limit with `fundingInfo`.

**DIRECT PROBE RESULT.** Probe retrieval UTC: 2026-08-10 (the raw response
receipts were created in `/tmp/qntylab-funding-probes-NRp8bo`). Examples:

| Probe | Result |
|---|---|
| BTCUSDT, 2019-10-09 exact event boundary | HTTP 200, one row; `rateType=Regular`, `markPrice=""` |
| BTCUSDT, future-only range | HTTP 200, `[]` |
| invalid symbol `NOT_A_SYMBOL` | HTTP 200, `[]` |
| `limit=1001` | HTTP 200, Binance error object `code=99099990` |
| BTCUSDT, `startTime=endTime=1780272000001` | one row |
| same row with `startTime=1780272000002` | zero rows |
| BTCUSDT June 2026, limit 1000 | 90 rows, ascending `fundingTime` |
| same June 2026 range, limit 1 from first exact time | first row only |
| same range, limit 1 from second exact time | second row only |

The one-row response hash for the June-2026 first event is
`399bba705ec3d770d00dce2d9ed0629f98c2a986422adbfd036b234690a5992d`.
The 90-row response hash is
`01d38d5b8c8581388621015a2bc618673cac1ff51ff88672aea52f9bdb31bafd`.
The old 2019 response hash is
`ec7b70a77554d613e8b570ce50a39d90bd9e3814f5f37f38163b011b62cb2765`.

**DESIGN DECISION if this source were usable.** Paginate in ascending
`fundingTime` using exact inclusive boundaries, retain raw pages, reject a
non-increasing page transition, and deduplicate only an identical boundary
event after proving the same `(symbol, fundingTime)` and identical economic
fields. A gap, unexpected duplicate, missing required value, or unsupported
rate type fails closed. The endpoint does not publish an object checksum.

**HISTORICAL COVERAGE.** REST returned 2019 BTCUSDT data in the direct probe,
but this is not a certified retention horizon for every symbol. Symbol launch
and missing-history responses are represented as HTTP 200 empty arrays; empty
does not certify coverage.

**RATE TYPE.** The current documentation says `Regular` is the normal rate and
`Special` is an additional rate generated by stock dividends. All sampled
panel rows were `Regular`; no sampled panel event was `Special`. The official
source set inspected does not establish when `rateType` was introduced or
prove it is retroactively populated for every historical row. A 2019 REST row
did include the field. This remains an explicit fail-closed validation rule,
not an assumption that `Special` cannot occur.

**AUTHENTICATION CLASS.** `OFFICIAL_BINANCE_REST_PROVENANCE_BOUND`, not
publisher-checksum authenticated. A future materializer must retain endpoint,
exact query parameters, retrieval timestamp, HTTP status/headers, raw response
bytes and SHA-256, normalized response digest, page chain, first/last
`fundingTime`, and row count.

### REST `/fapi/v1/fundingInfo`

**SOURCE-SUPPORTED FACT.** Current documentation describes this endpoint as
information for symbols with FundingRateCap/Floor or fundingIntervalHours
adjustments. Its response includes `symbol`, adjusted cap/floor,
`fundingIntervalHours`, `disclaimer`, and currently also returned `updateTime`
in the direct response.

**DIRECT PROBE RESULT.** HTTP 200, 742 rows, raw SHA-256
`b1b35c630cf15d4e1c0af712bfa885a447010781dccf8df6e99d519bea073589`.

**DESIGN DECISION.** This establishes current/returned adjustment information
only. It does **not** establish historical adjustment chronology and must not
be used to infer historical intervals. Realized `fundingTime` values are the
accounting chronology; a historical funding-rule engine is not required for
settlement accounting.

### PUBLIC ARCHIVE

**DIRECT PROBE RESULT.** Official archive objects exist under:

```text
data/futures/um/monthly/fundingRate/<SYMBOL>/<SYMBOL>-fundingRate-YYYY-MM.zip
```

The tested daily paths returned HTTP 404. Monthly objects contain one CSV
member named `<SYMBOL>-fundingRate-YYYY-MM.csv` with header:

```text
calc_time,funding_interval_hours,last_funding_rate
```

`calc_time` is an integer millisecond timestamp. There is no `symbol` column,
`markPrice` column, or `rateType` column. Small 2022/2024/2025 BTCUSDT and
2024 BCHUSDT/ALICEUSDT/OPUSDT/APTUSDT ZIPs all showed this schema.

Archive listing observations for monthly fundingRate objects:

| Symbol | First listed month | Latest listed month at probe | Object count |
|---|---:|---:|---:|
| BTCUSDT | 2020-01 | 2026-07 | 79 |
| BCHUSDT | 2020-01 | 2026-07 | 79 |
| ALICEUSDT | 2021-03 | 2026-07 | 65 |
| OPUSDT | 2022-06 | 2026-07 | 50 |
| APTUSDT | 2022-10 | 2026-07 | 46 |

The official listing is not a historical instrument-lifecycle authority.
Delisted-symbol archive presence must be tested per requested object; current
symbol discovery must not silently remove a frozen panel member.

**PUBLISHER AUTHENTICATION.** Every tested ZIP had a sibling `.CHECKSUM`.
The checksum text is `<sha256>  <exact-zip-filename>` and verification is
SHA-256 over the exact ZIP bytes. For example:

```text
3e0d30870672aa8f0f937881056e3cfd55913ae5c780cd50b33f2763aa0ba58e  BTCUSDT-fundingRate-2024-01.zip
```

The corresponding ZIP SHA-256 matched. The official repository documents the
same checksum procedure and warns that archived files may later be updated.
Therefore the scientific identity must include source object path, published
checksum text/hash, actual raw ZIP SHA-256, retrieval time, and retained raw
ZIP bytes. A later replacement must not overwrite an already-used object.

## ADVERSARIAL CHECK

1. **REST only returns recent history — PASS (for the claim tested).** A 2019
   BTCUSDT event was returned; retention remains symbol-dependent and must be
   checked per requested range.
2. **Pagination skips/duplicates boundary events — PASS.** Exact inclusive
   boundary probes returned the expected first/second event; production must
   retain and validate the page chain.
3. **Inclusive start/end duplicates pages — PASS.** Duplicate boundary rows
   are predictable and must be removed only by exact identity after validation.
4. **Archive schema differs across years — UNRESOLVED.** Tested 2022, 2024,
   2025 samples matched; broader historical schema certification is out of
   scope after the blocking mark gap.
5. **Old archive files omit markPrice — PASS.** All tested archive CSVs omit it.
6. **Old REST rows omit markPrice — PASS.** The field is present but empty in
   the 2019 row and the sampled 2022 panel rows.
7. **rateType absent historically — UNRESOLVED.** Tested REST rows include it,
   but archive files omit it and introduction chronology is undocumented in
   the inspected official sources.
8. **Current fundingInfo mistaken for historical truth — PASS.** It returns
   adjustment records/current state, not a historical chronology.
9. **Delisted history disappears from current discovery — UNRESOLVED.** The
   risk is real; no current-discovery substitution is allowed.
10. **Fixed panel silently shrunk — PASS.** The contract requires the entire
    panel and the report records empty/gap outcomes explicitly.
11. **Raw API called publisher-checksum authenticated — PASS.** It is labeled
    retrieval-provenance-bound only.
12. **Archive replacement silently changes prior evidence — PASS.** The
    required source-object/checksum/raw-byte identity freezes used evidence.
13. **Nearest-price approximation replaces settlement mark — PASS.** The
    contract forbids it; the mark gap blocks this phase.
14. **Funding timestamps inferred from 8-hour schedule — PASS.** Only returned
    `fundingTime` is authoritative; observed intervals are descriptive.
15. **Archive/API rate disagreement hidden — PASS.** The notation-only 2025
    difference is recorded; archive is not treated as complete truth.

## SOURCE CONTRACT DECISION

**Chosen architecture: `BLOCKED`.**

The strongest conditional architecture would be archive-primary plus exact
REST enrichment (`symbol + fundingTime` one-to-one) because the archive has
publisher-authenticated rate/time bytes and REST supplies mark/rateType.
However, the required historical 2022 enrichment is not available with a
usable associated mark. Choosing REST-primary would not cure this: REST is
not publisher-checksum authenticated and returns empty historical marks.

Publisher-authenticated evidence: exact official monthly ZIP bytes and sibling
SHA-256 `.CHECKSUM` objects, limited to `calc_time`, interval-hours, and rate.

Retrieval-provenance-bound evidence: REST raw JSON pages, including exact
`markPrice` and `rateType` where populated. This is not equivalent to a
publisher checksum.
